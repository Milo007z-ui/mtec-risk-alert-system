## สูตรหลัก

### 1. การกำหนดหน่วยวิเคราะห์ — DBSCAN

```
DBSCAN(eps = 200 ม., MinPts = 3, metric = haversine) บนพิกัด (LATITUDE, LONGITUDE)
```

MinPts = 3 มาจากนิยาม Black Spot ของออสเตรเลีย (อุบัติเหตุซ้ำอย่างน้อย 3 ครั้ง)

ผลรอบ `v2568-r7`: จุดเสี่ยงรวม **1,234 จุด** = core cluster 234 กลุ่ม (ครอบคลุม
3,460 เหตุการณ์) + noise point 1,000 จุด · กลุ่มใหญ่ที่สุด 455 ครั้ง

**ที่มาของ eps = 200 ม.** มีสองส่วนประกอบกัน

1. **ค่าฐานเชิงสถิติ** — ค่ามัธยฐานระยะห่างเพื่อนบ้านลำดับที่ 3 ของข้อมูลจริง
   ทั้ง 4,460 รายการ = **97.08 เมตร** เป็นค่าที่คำนวณได้ตรงจากการกระจายของข้อมูล
2. **sorted k-distance graph** ตาม Ester, Kriegel, Sander & Xu (1996) — เรียงระยะ
   เพื่อนบ้านลำดับที่ 3 จากมากไปน้อยแล้วหาตำแหน่งจุดข้อศอก พบว่าบริเวณ 200 เมตร
   อยู่ในช่วงที่ความชันเริ่มเปลี่ยนจากชันปานกลางเป็นชันน้อยลง

> ⚠️ วิธีหาจุดข้อศอกด้วยสายตา (elbow-by-eye) เป็นการตีความเชิงอัตวิสัย ผู้วิเคราะห์
> ต่างคนอาจอ่านตำแหน่งจากกราฟเดียวกันได้ไม่ตรงกัน ต่างจากค่ามัธยฐานที่ให้ผลเดียวแน่นอน
> ต้องระบุข้อจำกัดนี้ทุกครั้งที่อ้างที่มาของ eps

### 2. ดัชนีความรุนแรงอุบัติเหตุ — Severity Index

```
SI = (F + PI) / Total Accident
```

| สัญลักษณ์ | ความหมาย | หน่วย |
|---|---|---|
| `F` | จำนวนอุบัติเหตุที่ก่อให้เกิดการสูญเสียชีวิตในจุดนั้น | **ครั้ง** (ไม่ใช่จำนวนศพ) |
| `PI` | จำนวนผู้บาดเจ็บรวม (สาหัส + เล็กน้อย) | **คน** |
| `Total Accident` | จำนวนอุบัติเหตุทั้งหมดในจุดนั้น | ครั้ง |

จุดที่มักสับสน: `F` นับเป็นครั้ง แต่ `PI` นับเป็นคน ตามนิยามต้นฉบับ
(self-test ข้อ 1 ในสคริปต์ตรวจข้อนี้โดยเฉพาะ)

ที่มาของสูตร: วิทยานิพนธ์ของ **ณัฐพงศ์ ซื่อสัตย์ (2558)** ใช้สูตรเดิมไม่ดัดแปลง

สถิติเชิงพรรณนารอบ `v2568-r7` (1,234 จุด): mean 0.77 · median 0.67 · SD 1.77 ·
min 0.00 · max 54.00

### 3. EPDO (Equivalent Property Damage Only)

```
EPDO = 6.7F + 2.0S + 0.058M     (ล้านบาท)
```

`F`, `S`, `M` ในสูตรนี้นับเป็น **จำนวนคน** (เสียชีวิต / สาหัส / เล็กน้อย)
ต่างจาก `F` ในสูตร SI ที่นับเป็นครั้ง

น้ำหนักทั้งสามคือต้นทุนความสูญเสียต่อรายของ **TDRI ปีงบประมาณ 2565** ในหน่วยล้านบาท
ดังนั้น `EPDO = economic_loss ÷ 1,000,000` พอดี — ในโค้ดจึงเก็บทั้งสองค่าและมี
self-test ยืนยันความสัมพันธ์นี้ (ข้อ 6–7)

EPDO รวมทั้งชุดข้อมูล = **1,997.65 ล้านบาท** ค่านี้ไม่ขึ้นกับวิธีจัดกลุ่ม
(เปลี่ยน eps แล้วยอดรวมเท่าเดิม) เพราะคำนวณจากผลรวมระดับรายอุบัติเหตุ

### 4. การจำแนก 3 ระดับ

| ระดับ | เกณฑ์ | จำนวนจุด (r7) | ร้อยละ | EPDO รวม (ลบ.) | EPDO เฉลี่ย/จุด |
|---|---|---|---|---|---|
| 🟢 ต่ำ | SI < 1 | 670 | 54.3% | 662.97 | 0.99 |
| 🟠 ปานกลาง | 1 ≤ SI < 2 | 403 | 32.7% | 916.74 | 2.27 |
| 🔴 สูง | SI ≥ 2 | 161 | 13.0% | 417.94 | 2.60 |
| | **รวม** | **1,234** | **100.0%** | **1,997.65** | **1.62** |

ขอบล่างรวมอยู่ในชั้นบน — SI = 1.000 พอดีจัดเป็น "ปานกลาง" ไม่ใช่ "ต่ำ"
(self-test ข้อ 4 ตรวจข้อนี้)

**ที่มาของจุดตัด 1 และ 2:** ค่า SI ในชุดข้อมูลมีช่วงคงที่ยาวรอบเลขทั้งสอง —
เปอร์เซ็นไทล์ที่ 56 ถึง 84 ให้ค่า SI = 1.000 เท่ากันหมด และเปอร์เซ็นไทล์ที่ 88 ถึง 90
ให้ค่า SI = 2.000 เท่ากันหมด จุดตัดจึงตกอยู่บนรอยต่อธรรมชาติของข้อมูล ไม่ใช่เลขที่
ตั้งขึ้นลอย ๆ แต่ยังคงเป็นการเลือกด้วยดุลพินิจ ไม่มีทฤษฎีกำหนดตายตัว

## ⚠️ หลักการสำคัญที่สุด: Fixed-Schedule Recalibration

**ห้าม**คำนวณผลใหม่แบบ dynamic ทุกครั้งที่ระบบถูกเรียกใช้ — ระดับของจุดที่ไม่ได้
เปลี่ยนจริงจะลอยขึ้นลงทุกครั้งที่มีอุบัติเหตุใหม่เข้าแม้เหตุเดียว สีบนแผนที่จะ
"กะพริบ" โดยไม่มีเหตุผล

วิธีที่ถูกต้อง (ตามที่ implement ใน pipeline):

1. กำหนดรอบ recalibration ตายตัวล่วงหน้า — โปรเจกต์นี้ใช้ **ทุก 6 เดือน**
2. ถึงรอบจึงรัน `scripts/build_risk_points.py` ใหม่ แล้ว **ล็อกผลเป็นเวอร์ชัน**
   (ปัจจุบัน `v2568-r7` — snapshot ทุกรอบเก็บที่ `data/calibrations/`)
3. ระหว่างรอบ จุดใหม่ใช้ค่าของรอบปัจจุบันไปก่อน
4. เก็บ log ทุกเวอร์ชันไว้ตรวจสอบย้อนหลัง
5. หน้าเว็บอ่านเฉพาะผลที่คำนวณไว้แล้ว — ท้ายแดชบอร์ดระบุเวอร์ชันกำกับไว้

ที่มา: Srinivasan & Carter (2011), *Development of Safety Performance Functions for
North Carolina*, UNC HSRC/NCDOT หน้า 49-51 — คำนวณ Calibration Factor ตามรอบเวลา
ที่กำหนด ไม่ใช่แบบ dynamic

> หมายเหตุ: อ้างอิง**เฉพาะหลักการ recalibration ตามรอบเวลา**เท่านั้น ไม่ใช่แหล่งของสูตร
> ใด ๆ (เนื้อหาส่วน Negative Binomial Regression / SPF ต้องใช้ AADT ซึ่งชุดข้อมูลนี้ไม่มี)

> ⚠️ **เปลี่ยน eps = เปลี่ยนชุดจุดเสี่ยงทั้งชุด** ต้องอัปเดต `MOCK_ROUTE_IDS` ใน
> `js/gps.js` และตัวเลขใน README / เอกสาร / แดชบอร์ดทุกครั้ง

## ข้อจำกัด (ควรระบุในรายงาน)

1. **ปรากฏการณ์ chaining ของ DBSCAN** — ที่ eps = 200 ม. จุดข้อมูลเชื่อมต่อกันเป็น
   ลูกโซ่ตามแนวถนนที่หนาแน่น กลุ่มใหญ่ที่สุดมี **455 ครั้งในกลุ่มเดียว** (เทียบ 278 ครั้ง
   ที่ eps = 100 ม. และ 994 ครั้งที่ eps = 400 ม.) อาจครอบคลุมพื้นที่ยาวหลายกิโลเมตร
   ทำให้การตีความว่าเป็น "จุด" เฉพาะเจาะจงคลุมเครือ พิกัดที่ใช้แทนกลุ่มเป็นเพียง
   ค่าเฉลี่ยของสมาชิก อาจไม่ตรงตำแหน่งที่เกิดเหตุหนาแน่นจริง — กลุ่มขนาดใหญ่ควรตีความ
   ในระดับ "ช่วงสายทาง" มากกว่าระดับ "จุด"
2. **SI ของ noise point อ่านผิดความหมายได้ง่าย** — เมื่อ N = 1 ค่า SI เท่ากับจำนวน
   ผู้บาดเจ็บในเหตุการณ์นั้นตรง ๆ เหตุรถโดยสารครั้งเดียวที่มีผู้บาดเจ็บ 54 คนจึงได้
   SI = 54.00 สูงสุดในชุดข้อมูลทั้งที่เกิดเพียงครั้งเดียว **สิบอันดับแรกด้าน SI
   เป็น noise point ทั้งหมด** เวลารายงานตารางอันดับควรระบุชัดว่านับรวม noise หรือไม่
3. **SI เป็นค่าเฉลี่ยต่อครั้ง ไม่ใช่ผลรวม** — จุดที่เกิดเหตุถี่มากแต่บาดเจ็บเบาจะได้ SI ต่ำ
   เช่นกลุ่ม 455 ครั้งได้ SI เพียง 0.70 (จัดเป็นระดับ "ต่ำ") ทั้งที่มี EPDO 64.55 ล้านบาท
   สูงเป็นอันดับ 2 ของชุดข้อมูล — **ต้องรายงาน SI คู่กับ EPDO เสมอ** เพราะสองค่านี้
   ตอบคนละคำถาม (ความรุนแรงต่อครั้ง vs ความสูญเสียรวม)
4. **จุดตัด SI = 1 และ 2 เป็นการเลือกด้วยดุลพินิจ** แม้ตรงกับรอยต่อธรรมชาติของข้อมูล
   ก็ไม่มีทฤษฎีกำหนดตัวเลขนี้เจาะจง ถ้าถูกถามที่มาต้องตอบตรง ๆ
5. **ข้อมูล 167 เหตุการณ์ (3.6%) ไม่มีพิกัด** ถูกตัดออกจากการจัดกลุ่มทั้งหมด
6. **ชุดข้อมูลไม่มี AADT / ปริมาณจราจร / ความเร็วจริง** จึงคำนวณอัตราต่อปริมาณจราจร
   (crash rate) ไม่ได้ ทุกตัวชี้วัดในโมเดลนี้เป็นค่าดิบเชิงจำนวนล้วน จุดบนถนนที่มีรถ
   วิ่งมากย่อมมีโอกาสติดอันดับสูงกว่าโดยธรรมชาติ
7. **`รถที่เกิดเหตุ` นับจำนวนคัน ไม่แยกประเภทคู่กรณี** — เหตุรถชนคนเดินเท้านับเป็น
   1 คัน จึงถูกจัดเข้ากลุ่ม Single Vehicle
8. **ข้อมูลปีเดียว (2568)** ขณะที่นิยาม Black Spot ของออสเตรเลียอ้างช่วง 3–5 ปี
   จำนวนครั้งที่นับได้จึงต่ำกว่าที่นิยามต้นฉบับตั้งใจ
