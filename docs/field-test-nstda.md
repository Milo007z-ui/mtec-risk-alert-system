# แผนทดสอบภาคสนาม — อุทยานวิทยาศาสตร์ประเทศไทย (สวทช. ปทุมธานี)

สนามทดสอบ GPS จริง + เสียงเตือน + กล้อง EMMA บนถนนวงรอบภายในอุทยานวิทยาศาสตร์ฯ
คลองหนึ่ง คลองหลวง ปทุมธานี — ขับวนรอบเดียวได้จุดเสี่ยงครบทั้งสามระดับ

> ⚠️ **จุดเสี่ยง 3 จุดในชุดนี้เป็นข้อมูลสมมติ** แต่งขึ้นเพื่อทดสอบระบบเท่านั้น
> ไม่ใช่สถิติอุบัติเหตุจริงของถนนในอุทยานวิทยาศาสตร์ฯ **ห้ามนำตัวเลขไปรายงาน
> ปนกับชุดข้อมูล MOT** ทุกไฟล์ในชุดนี้มี `"synthetic": true` กำกับไว้แล้ว

## ทำไมต้องมีชุดข้อมูลนี้แยก

ชุดข้อมูลจริง (กทม. + ปริมณฑล 456 คลัสเตอร์) ไม่มีจุดเสี่ยงในเขตอุทยานวิทยาศาสตร์ฯ เลย
ขับทดสอบในพื้นที่ก็จะไม่มีอะไรเตือน จึงวางจุดสมมติไว้บนถนนของอุทยานฯ เอง
เพื่อทดสอบ **กลไก** ของระบบ (GPS → คำนวณระยะ → cooldown → เสียงเตือน → บันทึกภาพ EMMA)
โดยไม่ต้องขับออกไปหาจุดเสี่ยงจริงนอกพื้นที่ซึ่งจราจรหนาแน่นและควบคุมตัวแปรไม่ได้

## สนามทดสอบ

| รายการ | ค่า |
|---|---|
| เส้นทาง | ถนนวงรอบอุทยานวิทยาศาสตร์ฯ 1 รอบ (ตะวันตก → ใต้ → ตะวันออก → เหนือ) |
| ความยาว | 1.40 กม. · ที่ 30 กม./ชม. ใช้เวลา ~2 นาที 50 วินาที |
| ทิศทาง | ตามทิศทาง one-way จริงของถนนในอุทยานฯ ทั้งรอบ (ไม่มีช่วงวิ่งสวนเลน) |
| จุดเริ่ม–จบ | กลางถนนฝั่งตะวันตก (14.078172, 100.600808) ระหว่าง NECTEC กับ MTEC |
| จุดเสี่ยง | 3 จุด ครบ 3 ระดับ ระยะห่างกันน้อยสุด 277 ม. |

### จุดเสี่ยงทดสอบ 3 จุด

| ระดับ | id | พิกัด (lat, lng) | ตำแหน่งจริง | SI | ประโยคที่ต้องได้ยิน |
|---|---|---|---|---|---|
| 🟢 ต่ำ | `nstda_low` | 14.076465, 100.602376 | ถนนด้านทิศใต้ หน้าอาคาร สวทช. / ศูนย์หนังสือ | 0.50 | "…ใกล้จุดเสี่ยงต่ำ โปรดขับขี่ด้วยความระมัดระวัง" |
| 🟠 ปานกลาง | `nstda_medium` | 14.078698, 100.603521 | ถนนด้านทิศตะวันออก ทางแยกเข้าศูนย์ประชุมฯ | 1.40 | "…ใกล้จุดเสี่ยงปานกลาง โปรดลดความเร็ว และระวังรถตัดผ่านทางแยก" |
| 🔴 สูง | `nstda_high` | 14.080482, 100.601492 | ถนนด้านทิศเหนือ หน้าโรงงานต้นแบบ MTEC / BIOTEC | 2.33 | "…ใกล้จุดเสี่ยงสูง โปรดใช้ความเร็วให้เหมาะสม และขับขี่ระมัดระวังเป็นพิเศษ" |

พิกัดทั้งสามจุดเป็น node ของถนนจริงจาก OpenStreetMap ไม่ใช่จุดกลางสนามหญ้า
รถจึงวิ่งทับจุดพอดี (ระยะห่างจากเส้นทาง = 0.0 ม.) และตัวเลขอุบัติเหตุถูกตั้งให้
SI ตกคนละช่วงของจุดตัดจริงของโมเดล v3 (`<1` ต่ำ · `1–2` ปานกลาง · `≥2` สูง)
ระบบจึงจัดระดับเองจากสูตรเดิม ไม่ได้ยัดค่า level ลงไปตรง ๆ

### ⚠️ รัศมีเตือนต้องย่อจาก 500 ม. เหลือ 120 ม.

ระบบจริงเตือนที่ 500 ม. ซึ่งกว้างกว่าทั้งอุทยานฯ — ถ้าใช้ค่านี้ ทั้งสามจุดจะร้องพร้อมกัน
ตั้งแต่ยังไม่ออกรถ ทดสอบอะไรไม่ได้เลย สนามนี้จึงใช้ **120 ม. (ออกจากรัศมีที่ 150 ม.)**

เหตุผลที่เลือก 120: จุดที่ใกล้กันที่สุดห่าง 277 ม. → ครึ่งหนึ่งคือ 138 ม.
รัศมีที่แคบกว่า 138 ม. รับประกันว่าไม่มีทางอยู่ในรัศมีสองจุดพร้อมกัน
(สคริปต์สร้างข้อมูลมี `assert` ตรวจเงื่อนไขนี้ทุกครั้งที่รัน)

ที่ 30 กม./ชม. ระยะ 120 ม. = เตือนล่วงหน้า ~14 วินาที ซึ่งพอสำหรับตรวจว่า
เสียงพูดจบก่อนถึงจุดหรือไม่ **ตรรกะการเตือนทุกบรรทัดเหมือนระบบจริง เปลี่ยนแค่ตัวเลขรัศมี**

## วิธีรัน

### สร้าง/สร้างใหม่ชุดข้อมูลทดสอบ

```bash
python scripts/build_nstda_test_site.py
# -> data/risk_points_nstda_test.geojson   จุดเสี่ยง 3 จุด
# -> data/mock_route_nstda.geojson         เส้นทางวนรอบ 1.4 กม.
```

### ก. ทดสอบบนเว็บ (มือถือ + GPS จริง)

```bash
python -m http.server 8123
```

- ภาคสนาม: เปิด `http://<ip เครื่อง>:8123/test-nstda.html` บนมือถือในรถ
- ซ้อมในห้องก่อนออกไปจริง: `http://localhost:8123/test-nstda.html?mock=1&kmh=30`
  (ระบบจะวาดเส้นทางแล้วขับจำลองให้ดูทั้งรอบ)

> เบราว์เซอร์ให้สิทธิ์ GPS เฉพาะ `https://` หรือ `localhost` — ถ้าเปิดผ่าน IP ในวง LAN
> แล้วขอตำแหน่งไม่ได้ ให้ deploy ขึ้น GitHub Pages (เหมือนหน้าเว็บหลัก) แล้วเปิดจากลิงก์นั้นแทน

### ข. ทดสอบบนอุปกรณ์จริง (Raspberry Pi + ลำโพง + buzzer)

```bash
# เทอร์มินัลที่ 1 — API ต้องชี้ไปที่ชุดทดสอบ ไม่ใช่ชุดจริง
RISK_DATA_FILE=data/risk_points_nstda_test.geojson uvicorn api.server:app --host 0.0.0.0 --port 8000
#   PowerShell:  $env:RISK_DATA_FILE = "data/risk_points_nstda_test.geojson"
#   ตรวจว่าโหลดชุดถูก:  curl http://localhost:8000/api/health   -> dataset ต้องเป็น risk_points_nstda_test.geojson

# เทอร์มินัลที่ 2 — GPS จริง ด้วยรัศมีของสนามทดสอบ
python3 device/pi_alert_client.py --gpsd --alert-radius 120 --exit-radius 150

# ซ้อมในห้อง (ไม่ต้องมี GPS) — เดินตามเส้นทางทีละพิกัด
python3 device/pi_alert_client.py --route data/mock_route_nstda.geojson --once \
        --alert-radius 120 --exit-radius 150
```

**อย่าลืมกลับค่าเดิม** เมื่อเลิกทดสอบ: รัน API โดยไม่ตั้ง `RISK_DATA_FILE`
และรัน pi client โดยไม่ใส่ `--alert-radius/--exit-radius` (กลับไป 500/600 ม. อัตโนมัติ)

## ผลที่ต้องได้ (baseline จากการรันจำลอง)

ขับครบรอบ ต้องได้เสียงเตือน **3 ครั้ง จุดละครั้งเดียว เรียงต่ำ → ปานกลาง → สูง**

| ลำดับ | เตือนตอนขับไปได้ | จุด | ระยะขณะเตือน | ประโยคบอกระยะ |
|---|---|---|---|---|
| 1 | ~230 ม. | `nstda_low` (ต่ำ) | 118 ม. | "ข้างหน้าอีก 100 เมตร" |
| 2 | ~600 ม. | `nstda_medium` (ปานกลาง) | 119 ม. | "ข้างหน้าอีก 100 เมตร" |
| 3 | ~975 ม. | `nstda_high` (สูง) | 118 ม. | "ข้างหน้าอีก 100 เมตร" |

ช่วง 230 ม. แรกต้องเงียบสนิท (จุดเริ่มห่างทุกจุดเกิน 250 ม. — ใช้ตรวจว่าไม่มีการเตือนมั่ว)
และหลังผ่านจุดสูงจนกลับถึงจุดเริ่ม ต้องไม่มีเสียงเตือนซ้ำอีก

## การเก็บผลร่วมกับกล้อง EMMA

ระบบแจ้งเตือนกับกล้อง EMMA เป็นคนละกล่องกัน จับคู่ข้อมูลกันด้วย **เวลา** เท่านั้น
ก่อนออกรถจึงต้องตั้งนาฬิกาให้ตรงกันก่อน:

```bash
# บน Raspberry Pi — ตั้งเวลาให้ตรงเวลามาตรฐาน แล้วจดเวลาเริ่มรอบไว้
timedatectl set-ntp true && timedatectl status
date '+%Y-%m-%d %H:%M:%S'
```

- pi client พิมพ์ทุกบรรทัดพร้อม `[HH:MM:SS]` และพิกัดอยู่แล้ว — เก็บล็อกไว้ด้วย
  `python3 device/pi_alert_client.py --gpsd --alert-radius 120 --exit-radius 150 | tee test-run-1.log`
- นำเวลาที่ขึ้น `🔔 buzzer` ทั้งสามครั้งไปเทียบกับ timestamp ของภาพ/คลิปจาก EMMA
  เพื่อดูว่า "ตอนระบบเตือน กล้องเห็นอะไรอยู่" — ใช้ประกอบรายงานได้ทั้งภาพและเสียง
- ถ้า EMMA บันทึกพิกัดของตัวเองด้วย ให้เทียบพิกัดชุดเดียวกันได้อีกทาง
  (ค่าที่น่าสนใจ: GPS สองตัวต่างกันกี่เมตรบนถนนเส้นเดียวกัน)

## ข้อจำกัดของสนามนี้ที่ต้องเขียนในรายงาน

1. **ข้อมูลจุดเสี่ยงเป็นข้อมูลสมมติ** — ทดสอบได้แค่กลไกของระบบ ไม่ได้ยืนยันความถูกต้อง
   ของการจัดระดับความเสี่ยง (เรื่องนั้นต้องดูผลจากชุด MOT ในรายงานส่วนโมเดล)
2. **รัศมีเตือน 120 ม. ไม่ใช่ค่าที่ใช้จริง** — ตัวเลขระยะเตือนที่วัดได้จากสนามนี้
   จึงเทียบกับการใช้งานจริงบนทางหลวงไม่ได้ตรง ๆ
3. **ความเร็วในอุทยานฯ ต่ำ (~30 กม./ชม.)** — ไม่ครอบคลุมกรณีความเร็วสูงที่เสียงพูด
   อาจจบไม่ทันก่อนถึงจุด ถ้าจะทดสอบเรื่องนี้ต้องออกไปถนนพหลโยธินด้านนอก
4. **ถนนในอุทยานฯ เป็นถนนภายในหน่วยงาน** ไม่มีในระบบรหัสสายทางของกรมทางหลวง
   จึงเทียบกับแนวทาง AF (ช่วงถนน 1 กม. ตาม รหัสสายทาง + KM) ไม่ได้
