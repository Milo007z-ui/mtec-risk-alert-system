# แผนทดสอบภาคสนาม — อุทยานวิทยาศาสตร์ประเทศไทย (สวทช. ปทุมธานี)

สนามทดสอบ GPS จริง + เสียงเตือน + กล้อง EMMA บนถนนวงรอบภายในอุทยานวิทยาศาสตร์ฯ
คลองหนึ่ง คลองหลวง ปทุมธานี — ขับวนรอบเดียวได้จุดเสี่ยง **8 จุด** ครบทั้งสามระดับ

> ⚠️ **จุดเสี่ยงทั้ง 8 จุดเป็นข้อมูลสมมติ** แต่งขึ้นเพื่อทดสอบระบบเท่านั้น
> ไม่ใช่สถิติอุบัติเหตุจริงของถนนในอุทยานวิทยาศาสตร์ฯ **ห้ามนำตัวเลขไปรายงาน
> ปนกับชุดข้อมูล MOT** ทุกจุดมี `"synthetic": true` กำกับไว้แล้ว

## ทำไมต้องมีชุดข้อมูลนี้แยก

ชุดข้อมูลจริง (กทม. + ปริมณฑล 456 คลัสเตอร์) ไม่มีจุดเสี่ยงในเขตอุทยานวิทยาศาสตร์ฯ เลย
ขับทดสอบในพื้นที่ก็จะไม่มีอะไรเตือน จึงวางจุดสมมติไว้บนถนนของอุทยานฯ เอง
เพื่อทดสอบ **กลไก** ของระบบ (GPS → คำนวณระยะ → cooldown → เสียงเตือน → บันทึกภาพ EMMA)
โดยไม่ต้องขับออกไปหาจุดเสี่ยงจริงนอกพื้นที่ซึ่งจราจรหนาแน่นและควบคุมตัวแปรไม่ได้

0 ม. เป็น 8–11 ม. ซึ่งเล็กกว่าความคลาดเคลื่อนของ GPS มือถือทั่วไปอยู่แล้ว)

พิกัดทุกจุดเป็น node ของถนนจริงจาก OpenStreetMap ไม่ใช่จุดกลางสนามหญ้า รถจึงวิ่งทับจุดพอดี
และตัวเลขอุบัติเหตุถูกตั้งให้ SI ตกคนละช่วงของจุดตัดจริงของโมเดล v3
(`<1` ต่ำ · `1–2` ปานกลาง · `≥2` สูง) ระบบจึงจัดระดับเองจากสูตรเดิม ไม่ได้ยัดค่า level ลงไปตรง ๆ

| `nstda_medium` | "…ใกล้จุดเสี่ยงปานกลาง โปรดลดความเร็ว และระวังรถตัดผ่านทางแยก" (ทางแยก) |
| `nstda_w2` | "…ใกล้จุดเสี่ยงปานกลาง โปรดระวังรถเข้าออกพื้นที่ข้างทาง" (ทางเชื่อมเข้าออก) |
| `nstda_w5` | "…ใกล้จุดเสี่ยงปานกลาง โปรดลดความเร็วก่อนเข้าโค้ง และงดแซงในช่วงนี้" (ทางโค้ง) |
| ทุกจุดระดับต่ำ | "…ใกล้จุดเสี่ยงต่ำ โปรดขับขี่ด้วยความระมัดระวัง" |

### ⚠️ รัศมีเตือนต้องย่อจาก 500 ม. เหลือ 60 ม.

ระบบจริงเตือนที่ 500 ม. ซึ่งกว้างกว่าทั้งอุทยานฯ — ถ้าใช้ค่านั้นทุกจุดจะร้องพร้อมกัน
ตั้งแต่ยังไม่ออกรถ สนามนี้จึงใช้ **60 ม. (ออกจากรัศมีที่ 80 ม.)**

- จุดที่ใกล้กันที่สุดห่าง **71 ม.** → ถ้าอยากให้วงรัศมี "ไม่ซ้อนกันเลย" ต้องแคบกว่า 35 ม.
  ซึ่งที่ 30 กม./ชม. เหลือเวลาแค่ 4 วินาที พูดประโยคเตือนไม่จบก่อนถึงจุด
- จึงเลือก 60 ม. (~7 วินาทีที่ 30 กม./ชม.) **ยอมให้วงซ้อนกันบ้าง** แล้วให้กติกากันพูดทับ
  ใน `alert.js` จัดคิวเอง: เตือนจุดใกล้สุดก่อน จุดถัดไปรอจนพูดจบ ระดับสูงกว่าตัดคิวได้ทันที
  (นี่เป็นการทดสอบกลไกคิวเสียงไปในตัว ซึ่งเส้นทางจำลองเดิมที่จุดห่างกันมากทดสอบไม่ได้)
- ยังรับประกันว่า **ตอนรถอยู่ตรงจุดใด ไม่มีจุดอื่นอยู่ในรัศมี** เพราะ 60 < 71
  (สคริปต์สร้างข้อมูลมี `assert` ตรวจเงื่อนไขนี้ทุกครั้งที่รัน)

ลองค่าอื่นสดหน้างานได้จาก URL ไม่ต้อง deploy ใหม่:
`test-nstda.html?alert=40&exit=60` — บนอุปกรณ์ใช้ `--alert-radius 40 --exit-radius 60`

**ตรรกะการเตือนทุกบรรทัดเหมือนระบบจริง เปลี่ยนแค่ตัวเลขรัศมี**

### ก. ทดสอบบนเว็บ (มือถือ + GPS จริง)

- ซ้อมในห้องก่อนออกไปจริง: เติม `?mock=1&kmh=30` ต่อท้าย
  (ระบบจะวาดเส้นทางแล้วขับจำลองให้ดูทั้งรอบ)
- รันจากเครื่องตัวเอง: `python -m http.server 8123` แล้วเปิด `http://localhost:8123/test-nstda.html`

> เบราว์เซอร์ให้สิทธิ์ GPS เฉพาะ `https://` หรือ `localhost` — เปิดผ่าน IP ในวง LAN
> จะขอตำแหน่งไม่ได้ ให้ใช้ลิงก์ GitHub Pages ข้างบนแทน

### ข. ทดสอบบนอุปกรณ์จริง (Raspberry Pi + ลำโพง + buzzer)

```bash
# เทอร์มินัลที่ 1 — API ต้องชี้ไปที่ชุดทดสอบ ไม่ใช่ชุดจริง
RISK_DATA_FILE=data/risk_points_nstda_test.geojson uvicorn api.server:app --host 0.0.0.0 --port 8000
#   PowerShell:  $env:RISK_DATA_FILE = "data/risk_points_nstda_test.geojson"
#   ตรวจว่าโหลดชุดถูก:  curl http://localhost:8000/api/health
#   -> dataset ต้องเป็น risk_points_nstda_test.geojson และ total_points = 8

# เทอร์มินัลที่ 2 — GPS จริง ด้วยรัศมีของสนามทดสอบ
python3 device/pi_alert_client.py --gpsd --alert-radius 60 --exit-radius 80

# ซ้อมในห้อง (ไม่ต้องมี GPS) — เดินตามเส้นทางทีละพิกัด
python3 device/pi_alert_client.py --route data/mock_route_nstda.geojson --once \
        --alert-radius 60 --exit-radius 80
```

**อย่าลืมกลับค่าเดิม** เมื่อเลิกทดสอบ: รัน API โดยไม่ตั้ง `RISK_DATA_FILE`
และรัน pi client โดยไม่ใส่ `--alert-radius/--exit-radius` (กลับไป 500/600 ม. อัตโนมัติ)

## การเก็บผลร่วมกับกล้อง EMMA

ระบบแจ้งเตือนกับกล้อง EMMA เป็นคนละกล่องกัน จับคู่ข้อมูลกันด้วย **เวลา** เท่านั้น
ก่อนออกรถจึงต้องตั้งนาฬิกาให้ตรงกันก่อน:

```bash
# บน Raspberry Pi — ตั้งเวลาให้ตรงเวลามาตรฐาน แล้วจดเวลาเริ่มรอบไว้
timedatectl set-ntp true && timedatectl status
date '+%Y-%m-%d %H:%M:%S'
```

- pi client พิมพ์ทุกบรรทัดพร้อม `[HH:MM:SS]` และพิกัดอยู่แล้ว — เก็บล็อกไว้ด้วย
  `python3 device/pi_alert_client.py --gpsd --alert-radius 60 --exit-radius 80 | tee test-run-1.log`
- นำเวลาที่ขึ้น `🔔 buzzer` ทั้ง 8 ครั้งไปเทียบกับ timestamp ของภาพ/คลิปจาก EMMA
  เพื่อดูว่า "ตอนระบบเตือน กล้องเห็นอะไรอยู่" — ใช้ประกอบรายงานได้ทั้งภาพและเสียง
- ถ้า EMMA บันทึกพิกัดของตัวเองด้วย ให้เทียบพิกัดชุดเดียวกันได้อีกทาง
  (ค่าที่น่าสนใจ: GPS สองตัวต่างกันกี่เมตรบนถนนเส้นเดียวกัน)

## ข้อจำกัดของสนามนี้ที่ต้องเขียนในรายงาน

1. **ข้อมูลจุดเสี่ยงเป็นข้อมูลสมมติ** — ทดสอบได้แค่กลไกของระบบ ไม่ได้ยืนยันความถูกต้อง
   ของการจัดระดับความเสี่ยง (เรื่องนั้นต้องดูผลจากชุด MOT ในรายงานส่วนโมเดล)
2. **รัศมีเตือน 60 ม. ไม่ใช่ค่าที่ใช้จริง** — ตัวเลขระยะเตือนที่วัดได้จากสนามนี้
   จึงเทียบกับการใช้งานจริงบนทางหลวงไม่ได้ตรง ๆ
3. **ความเร็วในอุทยานฯ ต่ำ (~30 กม./ชม.)** — ไม่ครอบคลุมกรณีความเร็วสูงที่เสียงพูด
   อาจจบไม่ทันก่อนถึงจุด ถ้าจะทดสอบเรื่องนี้ต้องออกไปถนนพหลโยธินด้านนอก
4. **ความหนาแน่นของจุดสูงกว่าของจริงมาก** (8 จุดใน 1.4 กม.) — ใช้ทดสอบคิวเสียงได้ดี
   แต่ไม่ใช่รูปแบบที่พบบนถนนจริงในชุดข้อมูล MOT
5. **ถนนในอุทยานฯ เป็นถนนภายในหน่วยงาน** ไม่มีในระบบรหัสสายทางของกรมทางหลวง
   จึงเทียบกับแนวทาง AF (ช่วงถนน 1 กม. ตาม รหัสสายทาง + KM) ไม่ได้
