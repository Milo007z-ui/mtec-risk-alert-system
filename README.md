# ระบบแจ้งเตือนจุดเสี่ยงอุบัติเหตุ — กรุงเทพฯ และปริมณฑล

เว็บแอปแผนที่ (Leaflet + OpenStreetMap) ติดตามตำแหน่ง GPS แบบเรียลไทม์
เมื่อเข้าใกล้จุดเสี่ยงอุบัติเหตุในระยะ **500 เมตร** จะแจ้งเตือนด้วย**เสียงพูดภาษาไทย**
พร้อมแบนเนอร์บนจอ ระบุสาเหตุความเสี่ยงและคำแนะนำการขับขี่เฉพาะจุด

ข้อมูลจุดเสี่ยงมาจากสถิติอุบัติเหตุปี 2568 ของ **MOT Data Catalog**
(ไฟล์ `data/accident2025_1.xlsx` รวม **4,627 เหตุการณ์** — 1 ชีตต่อจังหวัด:
กรุงเทพมหานคร นนทบุรี ปทุมธานี สมุทรปราการ นครปฐม สมุทรสาคร)
นำมาจัดกลุ่มด้วย **DBSCAN (รัศมี 150 ม. ขั้นต่ำ 3 เหตุการณ์)** ได้จุดเสี่ยง **290 จุด**
แล้วให้คะแนนด้วย**โมเดล v2**: 4 เกณฑ์ × น้ำหนักเท่ากัน 25% → Percentile Rank →
แบ่ง 3 ระดับด้วย Jenks Natural Breaks (🔴 สูง 76 · 🟠 ปานกลาง 117 · 🟢 ต่ำ 97 จุด)

## DBSCAN: หลักการจัดกลุ่มอุบัติเหตุให้เป็น "จุดเสี่ยง"

พิกัด GPS ของเหตุที่เกิด "จุดเดียวกัน" ในโลกจริงไม่ตรงกันเป๊ะ จึงต้องรวมเหตุการณ์
ที่เกิดใกล้กันให้เป็นจุดเสี่ยงเดียวก่อนให้คะแนน — ใช้ **DBSCAN**
(Density-Based Spatial Clustering of Applications with Noise) ซึ่งมองหา
"บริเวณที่จุดหนาแน่น" ด้วยพารามิเตอร์ 2 ตัว:

- **eps (ε)** — รัศมีเพื่อนบ้าน ที่นี่ใช้ **150 เมตร** (ระยะ haversine บนผิวโลก)
- **min_samples** — จำนวนเหตุการณ์ขั้นต่ำในรัศมี ที่นี่ใช้ **3**

อัลกอริทึมจำแนกทุกเหตุการณ์เป็น 3 ประเภท:

| ประเภท | เงื่อนไข | ผลต่อระบบ |
|---|---|---|
| **Core point** | มีเพื่อนบ้าน ≥ 3 เหตุการณ์ในรัศมี 150 ม. | เป็นแกนของจุดเสี่ยง และ "ลาม" ต่อไปยัง core อื่นที่อยู่ในรัศมีกันได้ (chain) |
| **Border point** | อยู่ในรัศมีของ core แต่เพื่อนบ้านตัวเองไม่ถึง 3 | ถูกนับรวมเข้าจุดเสี่ยงข้างเคียง |
| **Noise** | ไม่เข้าเงื่อนไขทั้งสอง | เหตุกระจัดกระจาย ไม่นับเป็นจุดเสี่ยง (รอบนี้ 1,111 จาก 4,460 เหตุการณ์) |

เหตุผลที่ DBSCAN เหมาะกับงาน accident hotspot กว่าวิธีอื่น (เช่น K-Means):

1. **ไม่ต้องกำหนดจำนวนกลุ่มล่วงหน้า** — เราไม่มีทางรู้ก่อนว่ากรุงเทพฯ มีจุดเสี่ยงกี่จุด
2. **จับกลุ่มรูปทรงอิสระได้** — อุบัติเหตุเรียงตัวเป็นแนวยาวตามถนน/ทางโค้ง ไม่ใช่วงกลม
3. **แยก noise ออกเองโดยธรรมชาติ** — เหตุการณ์เดี่ยวๆ ที่เกิดกระจัดกระจายไม่ถูกบังคับ
   ให้เข้ากลุ่มใดกลุ่มหนึ่ง (K-Means บังคับทุกจุดเข้ากลุ่ม ทำให้ centroid เพี้ยน)
4. **ขั้นต่ำ 3 เหตุการณ์** สอดคล้องนิยาม Black Spot มาตรฐานออสเตรเลีย
   (อุบัติเหตุบาดเจ็บ/เสียชีวิต ≥ 3 ครั้งในช่วงเวลาที่กำหนด)

ผลลัพธ์: 4,460 เหตุการณ์ที่มีพิกัด → **290 จุดเสี่ยง** (ครอบคลุม 3,349 เหตุการณ์)
พิกัดจุดเสี่ยง = ค่าเฉลี่ยพิกัดสมาชิก, สถิติทุกตัว (ผู้เสียชีวิต มูลค่าความเสียหาย ฯลฯ)
รวมจากสมาชิกทั้งหมดของกลุ่ม

## Risk Score โมเดล v2 (4 เกณฑ์ × 25% = 100 คะแนน)

แต่ละจุดเสี่ยงได้คะแนนจาก 4 เกณฑ์อิสระต่อกัน (ตรวจแล้ว Spearman ทุกคู่ < 0.30)
ทุกเกณฑ์ normalize ด้วย **Percentile Rank** (ทนทานต่อ outlier, OECD/JRC 2008)
แล้วรวมด้วยน้ำหนักเท่ากัน:

| เกณฑ์ | วิธีคิดค่าดิบต่อจุด | อ้างอิงหลัก |
|---|---|---|
| 1. ความถี่อุบัติเหตุ | จำนวนเหตุการณ์ในกลุ่ม | Black Spot ≥3 ครั้ง (มาตรฐานออสเตรเลีย) |
| 2. มูลค่าความเสียหายเศรษฐกิจ | ตาย×6.7 ล้าน + สาหัส×2 ล้าน + เล็กน้อย×58,000 บาท | TDRI ปีงบประมาณ 2565 |
| 3. Single-Vehicle Ratio | % เหตุที่มีรถ ≤ 1 คัน (เก็บคู่ Multiple% ไว้วินิจฉัย) | FHWA Roadway Departure |
| 4. Geometric Complexity | น้ำหนักเฉลี่ยตามกลุ่ม conflict ของ "บริเวณที่เกิดเหตุ" — น้ำหนักคำนวณจาก FI Rate ของข้อมูลไทยเอง: ทางตรง 1.000 · Merging 1.011 · Diverging 0.835 · Crossing 1.356 | TxDOT Conflict Points + VDOT |

```
Risk Score = 0.25×Frequency + 0.25×EconomicLoss + 0.25×SingleVehicle + 0.25×GeometricComplexity
```

**แบ่ง 3 ระดับด้วย Jenks Natural Breaks** (รอบ v2568-r1): 🟢 ต่ำ ≤ 41.9 < 🟠 ปานกลาง ≤ 60.3 < 🔴 สูง

**Fixed-Schedule Recalibration (หลักการสำคัญที่สุดของ v2):** ค่าอ้างอิงทั้งหมด
(Percentile Rank, Jenks breaks, FI weights) คำนวณแล้ว "ล็อก" เป็นเวอร์ชัน
(`data/calibrations/v2568-r1.json`) — **ไม่คำนวณใหม่ทุกครั้งที่เปิดแอป**
ไม่งั้นคะแนนจุดเดิมจะลอยขึ้นลงเมื่อมีเหตุใหม่เข้าระบบแม้เหตุเดียว เปรียบเทียบข้ามเวลาไม่ได้
กำหนดรอบคำนวณใหม่ล่วงหน้า **ทุก 6 เดือน** (แนวทาง NCDOT/UNC HSRC 2011)
หน้าเว็บ (เรียลไทม์) แค่อ่านผลที่คำนวณไว้แล้ว — popup และแดชบอร์ดระบุเวอร์ชันรอบคำนวณเสมอ

รายละเอียดสูตรทุกเกณฑ์ + เหตุผลการเลือกวิธี + อ้างอิงครบ: **[docs/risk-score-criteria.md](docs/risk-score-criteria.md)**

## REST API สำหรับอุปกรณ์ (`api/server.py`)

เซิร์ฟเวอร์ FastAPI แจกจ่ายข้อมูลจุดเสี่ยงให้อุปกรณ์ภายนอก (Raspberry Pi, มือถือ ฯลฯ)
และเสิร์ฟหน้าเว็บเดิมไปพร้อมกัน — ใช้เซิร์ฟเวอร์เดียวแทน `py -m http.server` ได้เลย

```bash
pip install -r api/requirements.txt
python -m uvicorn api.server:app --host 0.0.0.0 --port 8000
# เว็บ:      http://localhost:8000
# API docs:  http://localhost:8000/docs   (Swagger UI อัตโนมัติ)
```

| Endpoint | ความหมาย |
|---|---|
| `GET /api/health` | สถานะเซิร์ฟเวอร์ + จำนวนจุดเสี่ยง |
| `GET /api/risk-points` | ทุกจุด กรองได้: `?level=high` `?province=นนทบุรี` `?min_score=55` |
| `GET /api/risk-points/nearby?lat=..&lng=..&radius=600` | จุดในรัศมี เรียงใกล้→ไกล พร้อม `distance_m` และ **`alert_message`** (ข้อความเตือนไทยสำเร็จรูป สร้างจากกติกา Dynamic Alert เดียวกับเว็บ) |
| `GET /api/risk-points/{id}` | รายละเอียดจุดเดียว + ปัจจัยเสี่ยง |

## ไคลเอนต์ Raspberry Pi (`device/pi_alert_client.py`)

สคริปต์สำหรับติดบนรถ (เช่น รถเมล์): อ่านพิกัด GPS ของรถ ถาม API ว่ามีจุดเสี่ยงใกล้ๆ ไหม
เมื่อเข้าใกล้กว่า 500 ม. จะพูดเตือนคนขับเป็นภาษาไทยผ่านลำโพง (espeak-ng)
ใช้กติกา cooldown ชุดเดียวกับหน้าเว็บ ใช้เฉพาะ Python standard library ไม่ต้อง pip install

```bash
# บน Raspberry Pi (ต่อ GPS USB + ลำโพง)
sudo apt install gpsd espeak-ng
python3 device/pi_alert_client.py --api http://<IP-เซิร์ฟเวอร์>:8000 --gpsd

# ทดสอบโดยไม่มี GPS: พิกัดคงที่ หรือจำลองเส้นทางจากไฟล์ (บรรทัดละ lat,lng)
python3 device/pi_alert_client.py --api http://localhost:8000 --test 13.665 100.534
python3 device/pi_alert_client.py --api http://localhost:8000 --route route.csv
```

## กติกาการแจ้งเตือน (ปรับได้ใน `js/alert.js`)

| ค่า | ความหมาย | ค่าเริ่มต้น |
|---|---|---|
| `ALERT_RADIUS_M` | รัศมีที่เริ่มเตือน | 500 ม. |
| `EXIT_RADIUS_M` | ต้องออกไกลกว่านี้ถึงจะ "เตือนซ้ำได้เมื่อกลับเข้ามา" (hysteresis) | 600 ม. |
| `REALERT_MS` | วนอยู่ในรัศมีเดิมนานเท่านี้ถึงเตือนซ้ำ | 5 นาที |

**Dynamic Alert** (`js/riskrules.js`): ข้อความเตือนประกอบจากกติกาตามเงื่อนไขจริงของจุด
เช่น ทางแยก/ทางโค้ง/จุดกลับรถ/ประวัติผู้เสียชีวิต/รถคันเดียวเสียหลักเป็นหลัก/ชนท้ายบ่อย
พร้อมคำแนะนำการขับขี่เฉพาะกรณี — ใช้ร่วมกันทั้งเสียงพูด แบนเนอร์ และ popup
ส่วน popup เพิ่ม**คำแนะนำเชิงวิศวกรรม**ตามรูปแบบปัญหา (Single-dominant → ไหล่ทาง/ราวกัน,
Multiple-dominant → สัญญาณไฟ/ช่องเลี้ยว)
